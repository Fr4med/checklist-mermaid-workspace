# Contributing

Start with `npm ci`, `npm run build` and `npm test`. Keep a proposed change focused and explain the user-visible behavior plus the checks you ran.

Use synthetic checklists, diagrams, chat identifiers and credentials in examples and tests. Do not include your deployment's account identifiers, owner keys, private project paths, screenshots of real data or generated secrets. Run a secret scan and inspect the actual diff before opening a pull request.

Preserve manual checkbox choices, stable task identifiers, revision checks, project-token scope and archived connections. Keep Checklist and Mermaid independent. For diagram selection changes, check zoom/pan coordinates, stale baselines, both preview types and narrow-screen controls.

The public source license is still a maintainer decision. This package does not grant a license by inference; review the repository's final license before distributing modified copies.
